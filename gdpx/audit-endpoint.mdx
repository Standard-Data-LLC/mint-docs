Use `POST /v1/evaluate` before canonical import. The job of this endpoint is narrow: find defects in one task specification, return the evidence, and stop there. It does not create source bundles, task revisions, runs, or certificates.

<Warning>
  This endpoint still runs v14. GDPx acceptance runs on Standard Data v15, so a clean response is useful, not dispositive. Use it to fix the task, not to claim acceptance.
</Warning>

Use [Define the work](/gdpx/benchmark-task-rubric-best-practices#define-the-work) for prompt findings, [Grade observable work](/gdpx/benchmark-task-rubric-best-practices#grade-observable-work) for rubric and verifier findings, and [Set difficulty](/gdpx/benchmark-task-rubric-best-practices#set-difficulty) for pass@1. For the complete package, see the [task taxonomy](/quickstart).

## Base URL

```text
https://task-feedback-vgmxhdw3ka-uc.a.run.app
```

## Authenticate

Every route except `/v1/healthz` requires a bearer token.

```bash
export STANDARD_DATA_API_KEY="<issued-separately>"
```

## Audit a file

Send multipart form data. The file field must be named `file`.

<CodeGroup>

```bash cURL
API_BASE="https://task-feedback-vgmxhdw3ka-uc.a.run.app"

curl --fail-with-body \
  --request POST "${API_BASE}/v1/evaluate" \
  --header "Authorization: Bearer ${STANDARD_DATA_API_KEY}" \
  --form "file=@/absolute/path/to/instructions.docx" \
  --form 'options={"declared_mode":"benchmark","end_target":"gdpx-v1","checks_to_run":["all"],"verbosity":"full","include_suggested_fixes":true}' \
  --max-time 1500 \
  --output evaluation.json
```

```bash HTTPie
API_BASE="https://task-feedback-vgmxhdw3ka-uc.a.run.app"

http --form POST "${API_BASE}/v1/evaluate" \
  Authorization:"Bearer ${STANDARD_DATA_API_KEY}" \
  file@/absolute/path/to/instructions.docx \
  'options={"declared_mode":"benchmark","end_target":"gdpx-v1","checks_to_run":["all"],"verbosity":"full","include_suggested_fixes":true}'
```

</CodeGroup>

## Options

| Field | Values | Behavior |
| --- | --- | --- |
| `declared_mode` | `benchmark`, `rl`, `sft`, `rlvr`, `rlhf`, `dpo`, `sdft`, `agentic`, `both` | Overrides inferred mode and selects the matching checks |
| `end_target` | Lowercase slug such as `gdpx-v1` or `customer-rfp-v1` | Records the requested customer destination |
| `checks_to_run` | `["all"]` or named sections | Limits the grader set |
| `verbosity` | `summary` or `full` | Controls response detail |
| `include_suggested_fixes` | Boolean | Includes or omits proposed fixes |

Use `rl` when the task is for training but the exact RL method is not fixed. Use `both` only when the same task genuinely belongs in training and evaluation; it is not a shortcut around choosing.

Declared mode wins. If you send `benchmark`, the endpoint grades the document as a benchmark task even when the extractor would have called it `sft`. Leave the field out only when you want the service to infer mode.

<Note>
  `end_target` is routing metadata here. It does not turn v1 into a customer RFP audit. Audit v2 owns that check through a pinned `protocols.lab_specs` revision, and any requirement without an evaluator stays deferred rather than being marked passed.
</Note>

To preflight a taxonomy-aligned task, include the delivery-package outline, required task metadata, rollout evidence bindings, failed-rollout analyses, and dataset-level failure taxonomy and distributions in the submitted Markdown or JSON document. The endpoint evaluates that document as content; these are not separate request fields.

<Warning>
  The current v1 parser does not enforce the new taxonomy contract. Review `ungraded_sections`, and do not treat an absence of findings as package acceptance. Canonical import validation remains the source of truth.
</Warning>

## JSON request

Use JSON when the input is already text or base64-encoded bytes.

```json
{
  "task_input": {
    "format": "markdown",
    "content": "# Task title\n\nTask instructions...",
    "filename": "instruction.md"
  },
  "options": {
    "declared_mode": "benchmark",
    "end_target": "gdpx-v1",
    "checks_to_run": ["all"],
    "guidelines_version": "v14",
    "verbosity": "full",
    "include_suggested_fixes": true
  }
}
```

`task_input.format` accepts `pdf`, `docx`, `markdown`, or `json`. PDF and DOCX content must be base64-encoded in JSON transport. The endpoint accepts one document, not a Harbor directory or ZIP.

## Response

```json
{
  "kind": "task_spec",
  "evaluation_id": "eval_...",
  "task_summary": {
    "detected_mode": "benchmark"
  },
  "audit_intent": {
    "declared_mode": "benchmark",
    "extracted_mode": "sft",
    "effective_mode": "benchmark",
    "mode_source": "customer_declared",
    "end_target": "gdpx-v1",
    "end_target_status": "recorded_not_enforced_by_v1"
  },
  "aggregate_verdict": {
    "ready_to_submit": false,
    "blocking_issues_count": 2,
    "warning_count": 3,
    "info_count": 1
  },
  "ungraded_sections": [],
  "guidelines_version_applied": "v14"
}
```

`task_summary.detected_mode` reports the effective mode for backward compatibility. On task-spec responses, `audit_intent` is omitted when neither `declared_mode` nor `end_target` is supplied.

Always read `ungraded_sections`. A clean verdict with material left ungraded is not a clean task.

## Retrieve an evaluation

```bash
curl --fail-with-body \
  --header "Authorization: Bearer ${STANDARD_DATA_API_KEY}" \
  "${API_BASE}/v1/evaluations/eval_..." \
  --output evaluation.json
```

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/v1/evaluations/{evaluation_id}` | Retrieve an evaluation owned by the API caller |
| `GET` | `/v1/whoami` | Validate the key and read its rate limit |
| `GET` | `/v1/healthz` | Check service health without authentication |

## Limits

- Maximum file size: `10 MB`
- Request ceiling: approximately `15 minutes`
- Rate limit: returned by `/v1/whoami`
- Idempotency keys: not supported

Do not retry while the original request is open. A retry can create a second evaluation. Errors return a top-level `detail` field.

## Import after review

Move to [Import approved tasks](/gdpx/import-approved-tasks) only after you have worked through the findings and Standard Data has provisioned import access. Audit v2 uploads the ZIP, sanitizes the bundle, and commits the immutable task revision.
