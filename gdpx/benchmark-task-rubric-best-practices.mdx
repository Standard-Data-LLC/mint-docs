GDPx measures whether a model can finish representative, economically useful knowledge work in a realistic environment. We evaluate the whole job: kickoff, source material, tools, observable work, final artifact, deterministic checks, and rubric.

<Info>
  GDPx does not use a universal pass-rate band. Core items should separate the models named in the written evaluation plan, while easier items may serve as anchors. A zero-pass task can stay only when it is demonstrably solvable, the verifier works, and criterion-level results still provide useful signal.
</Info>

## Find the right page

The guidance is split into four pages. Start with the part of the task you are working on:

- [Design and grade](/gdpx/benchmark-task-design): define the work, build the environment, and make the rubric observable.
- [Package the task](/gdpx/benchmark-task-package): assemble the Harbor task, task taxonomy, ZIP, and self-contained environment.
- [Evaluate and analyze](/gdpx/benchmark-task-evaluation): run acceptance checks, analyze failures, and document reward integrity.
- [Partner delivery and review](/gdpx/benchmark-task-delivery): run the required partner evaluation and prepare the final handoff.

## How the formats fit together

The [Harbor task](/gdpx/quickstart#the-runnable-task) is the portable runtime core. Source handoffs and canonical submissions are separate formats. [Package the task](/gdpx/benchmark-task-package) explains when to use each one.
