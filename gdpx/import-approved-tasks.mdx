`POST /api/v2/workspace-submissions` is the legacy draft workflow. It does not create a canonical v3 evidence-catalog candidate or certify a QC stage.

Use [API bundle upload](/gdpx/evaluation-bundle-upload) for current submissions. The [GDPx repository layout](/gdpx/quickstart) is a source export, not an alternative v2 intake specification.

## If a legacy draft is requested

1. Authenticate at `https://api.standarddata.io`.
2. Read `GET /api/v2/intake-capabilities` for readiness, required scopes, limits, and supported input.
3. Create the submission and follow its upload, completion, and polling relations.
4. Retain source hashes, revision IDs, warnings, and blockers.

Do not substitute v2 capability fields for the v3 contract. Do not assume that a stored draft has executed successfully.

## Move to the current workflow

Recover the exact runnable task and complete evidence. Normalize them against the live v3 schemas, preserve the source-to-canonical identity mapping, and follow Standard Data's admission plan.

A v2 manifest or repository `TASK.json` cannot be dropped into canonical v3 `TASK.json`. New submissions preserve earlier immutable records; they do not edit those records in place.
