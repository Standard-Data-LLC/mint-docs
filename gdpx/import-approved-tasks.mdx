`POST /api/v2/workspace-submissions` is a legacy draft-import workflow. It can retain draft task revisions for review. It cannot create a canonical v3 catalog candidate, pass a QC stage, or add a task to the active evidence catalog.

<Warning>
  Do not use v2 when your goal is entry into the active evidence catalog. Use [v3 evaluation bundle upload](/gdpx/evaluation-bundle-upload).
</Warning>

## When to use v2

Use this flow only when Standard Data explicitly directs you to create a legacy draft workspace.

| Workflow | Purpose | Can enter the active evidence catalog? |
| --- | --- | --- |
| `POST /v1/evaluate` | Review one document | No |
| `POST /api/v2/workspace-submissions` | Create legacy draft revisions | No |
| `POST /api/v3/gdpx-submissions` | Retain a v3 draft or submit task and evidence | Can create an active evidence-catalog candidate; final benchmark release still requires QC4 |

A v2 task shown in a legacy explorer remains a draft. It is not a v3 **Review Tasks** record and it is not a Wilderness **Results** record.

## Discover the v2 contract

```bash
export STANDARD_DATA_API_BASE="https://api.standarddata.io"
export STANDARD_DATA_API_KEY="<your-standard-data-api-key>"

curl --fail-with-body \
  --header "Authorization: Bearer ${STANDARD_DATA_API_KEY}" \
  "${STANDARD_DATA_API_BASE}/api/v2/intake-capabilities" \
  --output v2-intake-capabilities.json
```

Follow the returned v2 relations and limits. Do not use this response to infer v3 modes, schemas, adapters, or availability.

## Submit the workspace

The v2 flow uses the legacy workspace contract returned by its capability response:

1. create the workspace submission;
2. upload the exact ZIP through the returned storage relation;
3. complete the upload;
4. review any adapter preview or mapping warnings; and
5. poll the returned submission relation.

Keep runnable task files, supplied evidence, and review documents separated according to the v2 contract. Uploaded results remain supplied evidence; v2 does not validate managed execution.

## Interpret the result

The import may create immutable draft revisions or remain blocked with source-package findings. Neither outcome adds the task to the active evidence catalog or released GDPx benchmark.

To move a draft task into the current GDPx workflow:

1. recover the exact runnable task and complete workspace;
2. prepare the canonical v3 `TASK.json` and evidence files from the live schema;
3. obtain a qualifying managed QC1 attempt through Standard Data; and
4. submit through `/api/v3/gdpx-submissions`.

Do not copy a v2 intake manifest or partner `TASK.json` into the strict v3 schema. Normalize the task explicitly.

## Immutable revisions

An import creates a new draft revision. It does not edit an older revision in place. Keep the source ZIP hash, returned revision IDs, and blocker records so later normalization can cite the exact source.
