Wilderness **Results** shows retained evidence selected for the active evidence catalog. From that record, a reviewer should be able to explain what the agent saw, did, and produced, how the verifier graded it, and why the final score is correct. This catalog state is separate from inclusion in the released GDPx benchmark.

<Note>
  **Review Tasks** is a separate surface. It may show a retained, blocked draft without a rollout or complete evidence. Seeing a draft there does not mean the task passed QC1 or entered Results.
</Note>

## What the reviewer sees

The default review view includes:

1. run configuration and execution outcome;
2. the exact task prompt and relevant agent-visible context;
3. the final response and native work products;
4. the rubric scorecard and score reconciliation;
5. the observable trajectory; and
6. artifacts, provenance, and completeness.

Show an unavailable optional metric as **Not supplied**, never zero.

## Required source sections

A countable rollout needs all six sections:

| Section | Required content |
| --- | --- |
| **Problem** | Exact task instruction and relevant agent-visible context |
| **Setup Logs** | Environment build, initialization, reset, dependency, and harness output |
| **Agent Logs** | Ordered observable messages, tool calls, tool results, state changes, and errors |
| **Results** | Final response, produced work products, patches, and result metadata |
| **Test Logs** | Raw verifier and per-test output with criterion bindings |
| **Grading** | Criterion decisions, rationale, evidence references, and score reconciliation |

Use `not_applicable` only when a section genuinely cannot apply, and give a source-grounded reason. Missing evidence does not qualify.

## Prompt and work products

Put the exact prompt before the model response. Preserve native artifacts such as spreadsheets, documents, drawings, images, and code. A rendered preview can help, but the hash-bound native download remains authoritative.

Include every work product the verifier graded. A text summary cannot stand in for a missing workbook, document, patch, or other deliverable.

## Rubric scorecard

Each criterion must show:

- the stable criterion ID and exact wording;
- its weight or aggregation role;
- `passed`, `failed`, `partial`, `blocked`, `not_applicable`, or `unscored`;
- the verifier rationale; and
- direct references to the event, test, output, or artifact used as evidence.

The summary must show the reported score, recalculated score, aggregation rule, threshold, hard gates, and reconciliation status. If the score does not reconcile, acceptance is blocked.

## Observable trajectory

Keep observable messages, assistant responses, tool calls, tool results, relevant state transitions, produced artifacts, errors, and the final stop condition in order.

Do not call this chain of thought. GDPx neither requires nor displays private model reasoning. Remove actual credentials, signed URLs, and provider-private fields, but preserve the rest of the observable content instead of replacing it with a blanket redaction or summary.

If a trajectory is too large to render inline, retain the complete artifact and show a bounded preview. The preview does not replace the full retained evidence.

## Run metadata

Retain the values the harness emits, including:

- model, provider, and immutable model revision when available;
- harness and harness version;
- prompt and tool configuration;
- environment and verifier versions;
- turn, token, time, and cost data;
- budgets, timeout, retry policy, and stop reason; and
- task, run, rollout, and artifact identities.

Never fabricate missing metrics. Record them as not supplied.

## Failure analysis

Every failed attempt used in review needs a readable failure-analysis summary tied to the same task, run, and rollout. The summary must identify the first observable failure, affected tests or criteria, failure origin, evidence references, solvability, and any required repair.

The optional [rollout-analysis endpoint](/gdpx/benchmark-rollout-analysis) returns supporting analysis. If you use it, keep the request and response beside the rollout. Its response does not replace the trajectory, verifier output, criterion ledger, or human QC decision.

## Evidence completeness

A rollout is incomplete if any required evidence body is missing, truncated at the source, attached to another attempt, or represented only by an ID or aggregate.

An adapter may map and preserve existing evidence. It cannot reconstruct content the source never retained.

## API readback

The canonical bundle format is documented under [Evaluation bundle upload](/gdpx/evaluation-bundle-upload#canonical-zip-layout).

Once the active evidence catalog selects a rollout, retrieve the exact retained evidence with:

```text
GET /api/v3/tasks/{task_revision_id}/runs/{run_id}/rollouts/{rollout_id}
```

This route is not a general pre-admission preview. A retained candidate outside the active evidence catalog normally returns `404`.

Confirm that every returned artifact matches its declared path, size, media type, and SHA-256.

Backend readback confirms the retained evidence record; the separate benchmark tracker records QC2–QC4 program review.
