Every rollout published in Wilderness opens on **Master**. Master uses `gdpx-master-evidence/1.1.0` and is a readable projection of retained evidence. It does not replace or fabricate the six forensic source sections.

<Info>
  A displayed score must be explainable criterion by criterion. If the source evidence cannot support that explanation, the rollout is incomplete and is not published in Wilderness Results.
</Info>

## What Master shows

Master presents the evidence in review order:

1. Run statistics and execution outcome.
2. Exact task prompt and relevant agent-visible context.
3. Final model answer and primary work product.
4. Rubric scorecard and score reconciliation.
5. Collapsed observable trajectory.
6. Artifacts, provenance, transformations, and completeness.

The statistics header may include score, threshold, tests, turns or steps, tool calls and errors, input and output tokens, peak context, duration, cost, model, harness, judge or verifier, timestamps, and stop condition. An unavailable optional metric is labeled `Not supplied`; it is never displayed as zero.

The execution label comes from Audit, not from an uploader-provided claim. A qualifying QC1 run shows managed execution validation only when its exact task, workspace inventory, run, rollout, evidence files, and runtime receipt match an operator-authenticated managed-execution approval. Otherwise, the evidence remains `not_execution_validated` and archive-only.

### Prompt and answer

Master renders the exact prompt before the model response. Plain text and Markdown are readable without opening raw JSON.

The answer area shows the final response and the primary work product. Document, PDF, spreadsheet, image, and code artifacts use their native previewers when available and retain a download link to the hash-bound source artifact. A server-supplied, hash-attested presentation is preferred. For verified Office files without one, Wilderness may build a bounded local preview from the downloaded bytes after checking the declared generation, size, and SHA-256; the immutable source download remains authoritative.

### Rubric scorecard

The scorecard appears immediately after the answer. Each criterion shows:

- its exact wording and stable ID;
- weight and awarded contribution when applicable;
- `passed`, `failed`, `partial`, `blocked`, `not_applicable`, or `unscored` as text and an icon;
- the grader rationale;
- direct and dependency-cascaded results; and
- links to the exact event, test, output, or artifact used as evidence.

Color reinforces status but is never the only indicator. Failed and blocked criteria open by default. Passed criteria start collapsed. Reviewers can search criteria and filter by **All**, **Failed**, **Blocked**, or **Unscored**.

The summary shows the reported and calculated totals, aggregation rule, threshold, hard gates, and reconciliation status. A non-reconciling score is a publication blocker, not a UI warning.

### Observable trajectory

The trajectory shows model-visible messages, assistant responses, tool calls, tool results, state transitions, produced artifacts, and errors in order. Long tool payloads use progressive disclosure and link to retained raw evidence.

Do not call this view “chain of thought.” Hidden or private reasoning is not collected or displayed. A reviewer may see only observable messages and operational actions that were part of the retained run.

### Pre-launch execution rejection

A trusted-runtime attestation rejection is infrastructure evidence, not a model score. Master labels the attempt **Execution rejected before scoring** and may show only the bounded reason (`missing_marker`, `duplicate_marker`, `marker_not_first`, `malformed_marker`, `missing_sidecar`, `malformed_sidecar`, `mismatched_sidecar_a`, `controller_timeout`, or `controller_terminated`); marker count and first-line check; capped stdout and stderr line and byte counts with truncation flags; return code when available; elapsed time; and sidecar presence and validity. It never displays raw stdout, stderr, marker values, or sidecar bytes from that diagnostic. No rollout, score, or QC credit is created.

## Source sections

The forensic tabs remain available after Master:

| Tab | Required contents |
| --- | --- |
| **Problem** | Exact task instruction, runtime kickoff, and agent-visible context |
| **Setup Logs** | Environment build, initialization, reset, dependency, and orchestration evidence |
| **Agent Logs** | Observable messages, tool calls, tool results, and agent-visible errors |
| **Results** | Final response, produced artifacts, patches, and result metadata |
| **Test Logs** | Per-test output, status, criterion bindings, and verifier runtime evidence |
| **Grading** | Criterion decisions, rationale, judge/verifier fingerprints, and score reconciliation |

Each tab is either complete or explicitly `not_applicable` with a source-grounded reason. A missing section cannot be converted to `not_applicable` merely to satisfy admission.

## Access and permanent omissions

Every authenticated tenant user with `tasks:read` receives the same complete sanitized Master projection and all six source sections. Wilderness does not require a separate trace-review role, companion entitlement, or client-side evidence gate. Do not display an “authorized viewer only” message to a tenant reader who already has `tasks:read`.

Sanitization is a narrow ingestion boundary, not a presentation mode. After actual or live credentials, private reasoning, and provider-private fields have been removed, render the remaining prompt, messages, tool inputs and outputs, tests, grading, and work-product content verbatim. Never replace retained sanitized content with `Content redacted`, `[OMITTED SENSITIVE SUPPLIED CONTENT]`, a structural-event-only table, or another blanket placeholder. If the source bundle did not retain a body, label it `Not retained`; do not imply that a viewer permission can reveal it.

An approved internal-QA attestation is the narrow exception for credential-like literals that are proven synthetic, fixture-bound, offline, and unreachable. Those source and Master bytes render verbatim. Master shows the attestation status, corpus hash, classification provenance, and active authority generation without adding another permission gate. Revoked, mismatched, incomplete, or external-origin evidence fails closed.

For this exact path, the rollout response declares `review_access.access_class: "internal_qa"`, `review_access.classified_synthetic_fixture_values_present: true`, `redaction_policy.credentials_omitted: true`, `redaction_policy.actual_credentials_omitted: true`, and `redaction_policy.credentials_omitted_semantics: "actual_credentials_only"`. It also declares that hidden reasoning and provider-private state remain omitted. A viewer must preserve the attested fixture bytes under that complete server-authorized boundary; it must not apply a second credential-pattern filter in the browser. The semantics do not authorize actual credentials or private reasoning.

Internal-QA evidence exists only in the V3 review-evidence store and exact V3 task/run/rollout routes. It does not create a V2 task, workspace, run, readiness record, family, data sheet, or catalog member. This separation prevents a review-only fixture from leaking into external task discovery through a stale legacy index.

These boundaries remain permanent:

- anonymous users cannot read tenant evidence;
- one tenant cannot read another tenant’s evidence;
- actual or live credentials, signed URLs, secret values, and provider-private state are omitted;
- hidden or private reasoning is omitted; and
- verifier-only gold material remains outside the rollout projection when disclosure would leak the benchmark answer.

Removing an unnecessary viewing gate does not weaken these tenant, secret, or benchmark-integrity boundaries.

## Completeness and provenance

Master identifies whether a field was supplied canonically, normalized from a source bundle, or derived from retained legacy evidence. A derived field includes its source references, transformer version, hashes, and timestamp. Master also binds the exact `task_content_sha256` and `workspace_inventory_sha256` used for execution.

The projection may join or format existing facts. It may not invent a missing final answer, criterion decision, rationale, test result, score, or artifact. If one of those primary facts is unavailable, the task remains blocked from the active GDPx catalog.

Use `GET /api/v3/tasks/{task_revision_id}/review-readiness` to inspect current-policy blockers, rights authority, and managed-execution approval. Use `GET /api/v3/tasks/{task_revision_id}/runs/{run_id}/rollouts/{rollout_id}` to retrieve the same complete retained evidence projection that Master renders. Historical evidence remains immutable, but only current-policy review-ready evidence appears in Wilderness Results.

Reader visibility follows the active v3 catalog, not a legacy task or run row. A staged compatibility projection remains invisible until the catalog admits the exact task revision, run, rollout, Master hash, and evidence hash. Wilderness must not show a rollout row unless the corresponding Master route is admitted and retrievable.
