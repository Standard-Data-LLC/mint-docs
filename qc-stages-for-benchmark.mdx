Before a task enters QC, it must use the [benchmark task package](/gdpx/benchmark-task-package). 

Partner Task Iteration (Until August 25th):

<Accordion title="QC1: Integrity in construction">
  Run one GPT-5.6 Luna smoke rollout on the exact task revision. Confirm that the environment, tools, source files, and verifier work. Retain the complete prompt, observable trajectory, final output, six forensic sections, criterion decisions, and score reconciliation. Fix construction or evidence-capture defects and repeat until one current-revision smoke is clean. Use [rollout analysis](/gdpx/benchmark-rollout-analysis) as judge-assisted evidence when the failure origin is unclear; it does not retain the rollout or advance the task.
</Accordion>

<Accordion title="QC2: Difficulty and reward integrity">
  Run repeated native frontier-harness rollouts. Confirm that rewards are stable, interpretable, and resistant to reward hacking. Review false positives and false negatives. If Luna is already saturated, keep the task in QC1, harden or drop it, and rerun. Saturated smoke results do not count as QC2.
</Accordion>

Final Evals for Benchmark Results (and iteration):

<Accordion title="QC3: Benchmark evaluation">
  Run 16 completed subject rollouts for each pairing in the current evaluation matrix. Analyze model failures, reward variance, unintended behavior, and verifier issues. Infrastructure retries, Oracle runs, and hinted runs do not count toward the 16 subjects.
</Accordion>

Research Paper Writeout Co-Development:

<Accordion title="QC4: Analysis and normalization">
  Review false positives and false negatives, cluster failure modes, run useful cross-harness checks, and decide final inclusion. Normalize accepted task and evidence revisions after that decision. Only a v3 submission that reaches `review_ready` may join the active GDPx catalog.
</Accordion>

See [Partner delivery and review](/gdpx/benchmark-task-delivery) for the full evidence contract.
